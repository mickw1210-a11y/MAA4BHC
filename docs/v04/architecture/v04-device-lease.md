# W03-02／W03-03：Windows跨项目实例租约与持有者诊断

核对日期：2026-11-16。范围：实现可离线竞争的Windows命名互斥体原语，按W03-01身份摘要锁定；本任务不接入任何设备派发入口。

## 行为

- `WindowsInstanceLease` 使用 `Global\\MAA4BHC.DeviceLease.v1.<sha256>` 内核互斥体名称，不创建项目内或项目外锁文件。
- 锁名只由 `DeviceInstanceIdentity.lease_key` 产生。项目路径、ADB路径和端口不参与，因此不同项目副本对同一身份竞争同一个机器级互斥体。
- 独立专用线程持有互斥体并负责释放，避免调用方在线程切换后无法释放Win32线程所有权互斥体。
- 竞争者返回 `conflict`。如果其他进程在前一持有者退出时仍保有该内核对象句柄，Win32可能返回abandoned；实现会把状态报告为`abandoned`并保持隔离，不自动释放。
- 非Windows环境、命名对象创建／等待错误或等待状态不明均失败关闭。调用方必须以身份未知／租约错误停止设备操作。

## 验证与界限

`tests/test_device_lease.py` 启动独立Python子进程，验证另一项目路径下相同身份无法竞争已持有租约；正常释放后第二个进程能够取得锁。另一个崩溃注入试验发现：若持有者退出时已无其他进程打开该命名对象，Windows销毁对象；之后创建者得到新锁而看不到abandoned。故命名互斥体只解决活跃竞争，不能单独验证崩溃后的动作状态。测试使用随机合成身份，不连接MuMu或ADB，也不接游戏控制器。

此原语尚未接到 `SessionLease`、Bridge、主窗口、开发CLI或所有设备动作入口。现有背包会话锁继续按项目目录工作，不能据此宣称设备已排他；统一接入属于W03-07。

## W03-03持有者与本机诊断

- 活跃租约通过`Local\\MAA4BHC.DeviceLeaseOwner.v1.<sha256>`共享映射发布进程PID、持有线程ID、进程创建FILETIME、取得时间和身份摘要。互斥体本身使用`Global\\...`；共享映射限同一Windows登录会话，不要求管理员创建全局文件映射。跨会话读取失败会保留冲突并将持有者标为unknown。
- 持有项目在`runtime/logs/device-leases/<sha256>.jsonl`追加`acquired`和`release_requested`事件并flush/fsync；只含本机PID/TID、进程创建标记、时间和身份摘要，不写项目根、ADB路径／地址、账户或凭据。文件不上传、不自动清理。路径被限制在当前项目根下；日志损坏或身份不符时拒绝读取。
- 竞争者能在同一会话读取活跃持有者并以PID加进程创建FILETIME判断`alive`、`exited`、`pid_reused`或`unknown`。进程存活不等于游戏动作已核实；冲突仍须停止。
- 5项定向子进程测试和333项Python完整回归退出码0；测试验证共享PID／存活状态、只写项目内诊断、损坏日志拒绝，以及崩溃后项目A的本机日志对项目B不可见。后一试验复现W03-04风险：Mutex没有持久所有者记录；进程退出且最后句柄关闭后，项目B会创建新锁。

## W03-04恢复门槛

2026-11-17移交复核将此项明确为当前接口缺口。已有诊断根检查限制当前项目树，其他副本还缺少日志发现与共享持久动作状态。项目内替代方案可继续设计和离线验证，项目外持久存储的必要性尚未证明。后续按具体实现证据解除关口。

跨项目副本恢复必须能读取崩溃持有者和未决动作证据。当前持久诊断按项目根保存，无法在项目B访问项目A记录；共享内存随句柄关闭消失。项目规则要求产物留在项目目录，项目外持久存储需另行决定；本轮未写入注册表、用户配置目录或其他项目外位置。因此W03-04保持受阻，且W03-02租约尚不接设备派发。若持有者状态或上次动作结果不明，必须停止，不能以新租约取得成功作为恢复许可。
