# 小游戏能力开放契约（W02-07）

代码：`app/game_capability.py`。当前范围严格为五个稳定ID：`candy-party`、`skewer-master`、`burger-day`、`starlight-mix`、`animal-bath`。新增或同名游戏不能自动进入v0.4能力表。

`CapabilityEvidence`以不可变布尔证据记录四个条件：规则已核实、模拟通过、无辅助道具死局目标通过、真实动作适配器通过。状态由证据推导，调用方不能直接把卡片改成“可执行”：

| 状态 | 证据条件 | 当前含义 |
| --- | --- | --- |
| `rules_unverified` | 规则证据缺失 | 游戏动作关闭 |
| `rules_verified` | 规则已核实，模拟尚未通过 | 可继续模拟施工，真实动作关闭 |
| `simulation_only` | 模拟已通过，但无死局目标或真实适配器仍未通过 | 可以用于离线模拟，真实动作关闭 |
| `execution_ready` | 规则、模拟、无死局目标及真实适配器全部有通过证据 | 静态能力门槛满足，仍需运行时门禁 |

前置顺序也受校验：无规则证据不能标模拟通过；模拟未通过不能标无死局目标或真实适配器通过。各款只能独立登记，不能用一款结果代表五款。v0.4当前五款仍按各自规则卡保持`rules_unverified`；模型和模拟没有被本任务宣称完成。

`execution_ready`不授予游戏消耗权限，也不表示当前活动开放、页面可识别、设备排他、成本／预算已知或本次计划获批。真实派发前仍要满足W03／W04的设备和画面门禁、活动与预算检查、停止条件及有效用户授权。没有R23证据时不得进入执行就绪状态。

离线验证：`tests/test_game_capability.py`覆盖五款白名单、逐级状态、无死局与适配器双门槛、错误证据顺序、严格布尔值及越界游戏拒绝。此契约未接UI、规则模拟器或设备控制器。
