# 存储提交与游戏动作边界（W02-09）

代码：`app/storage_contract.py`。存储使用独立的`StorageCommitRequest`：稳定`commit_id`、来源`observation_id`和不可变负载字节。回执必须与提交ID及SHA-256摘要一致。重试仅接受同一请求对象，使用相同键和相同字节；同一ID若对应不同内容，应由存储适配器拒绝，不能覆盖旧提交。

`retry_storage_commit`只接收`StorageCommitter`和提交请求，不接收`DeviceExecutor`、`ActionIntent`或任何点击／导航回调。它仅对明确标记为可重试的存储错误做调用方指定次数的有界重试；冲突、校验和其他错误直接停止。已提交但回执丢失时，适配器须用相同ID和内容实现幂等核对，不能把“提交未知”当作新交易。

游戏动作结果仍由W02-05的`ActionResult`独立表示。游戏动作最多提交一次；保存失败或保存结果未知时，只重试同一数据提交，不重新执行游戏动作。设备动作意图日志由W03-08实现，正式库存由W09实现。现有`inventory_storage_sample.py`与其他样例仍只允许项目临时目录，继续作为实验；本任务没有接入或迁移真实库存。

离线验证：`tests/test_storage_contract.py`用合成字节和内存适配器验证同一请求重试、有界失败、错误回执停止、不可重试错误停止，以及存储契约导入不加载执行器或设备控制器。无真实游戏数据和文件落盘。
