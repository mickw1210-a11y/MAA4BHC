# W02公共契约离线流程

代码：`app/task_status.py`提供UI可消费的`phase`、中文`label`、通俗`message`和可选`reason`。进入`needs_attention`必须提供可理解原因，不能只传异常栈。视图数据当前尚未接入主窗口；W06负责界面联动。

`tests/test_task_contract_flow.py`以虚拟观察和内存执行／存储适配器串联W02契约：

- 成功：先核任务依赖和当前画面，模拟一次已核实成功；存储短暂失败后以同一请求重试，动作调用数保持1。
- 等待：体力等待不允许直接进入运行；返回准备状态后才能重新核对并运行。
- 停止：必须经过`stopping`到`stopped`；恢复必须由用户显式发起。
- 失败：动作后置观察证实未达到预期时进入`needs_attention`，UI负载包含具体原因，不能标记完成。
- 提交未知：保留“已提交但未核实”，输出核对原因，不重放动作。
- 旧画面：指纹不匹配时动作保持未提交，UI能取得“画面已变化”原因。
- 当前五款能力仍全部规则未核实；离线通用流程不会因此伪装成小游戏模拟或开放执行。

此样例不调用Bridge、ADB、设备控制器、真实小游戏或正式库存；状态视图模型也未直接嵌入主窗口。它验证公共数据边界及UI可读的返回内容，不替代W03设备排他／统一派发、W06实际UI接入、W09正式存储或任何实机验收。

验证：`tests/test_task_contract_flow.py` 7项定向测试。完整Python回归按账本记录。
