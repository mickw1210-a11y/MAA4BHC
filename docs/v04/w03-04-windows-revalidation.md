# W03-04 Windows 双副本复验清单

状态：待目标 Windows 执行。该清单只用合成设备身份和项目内临时目录，不连接 MuMu、ADB 或游戏。

## 前置

- 将本任务代码与测试带到目标 Windows 项目副本后，在项目根运行。
- 使用项目 Python 3.12 环境；不要调用系统中可能较旧的 Python。
- 工作目录、分支和改动须符合当前 ASUS 交接。临时目录由测试创建在 .cache/tmp/，测试结束自动清理。
- 不提供真实实例编号、ADB 地址、账号或截图。设备租约名称采用测试随机身份。

## 一次运行

在 PowerShell 项目根直接执行：

    & .\.venv\Scripts\python.exe -W error::DeprecationWarning -m unittest -v tests.test_device_lease tests.test_device_recovery tests.test_device_recovery_windows

退出码必须为 0。Windows 上预期 19 项通过、0 项跳过；其中：

- test_device_lease：独立进程跨副本争锁、正常释放、最后句柄关闭后的既有崩溃复现。
- test_device_recovery：11 项合成状态、写入失败、缺失／损坏／错设备、PID复用、未决动作和观察证据用例。
- test_device_recovery_windows：活跃冲突后正常释放；持有者异常退出后的跨副本发现；崩溃发生在意图后或可能提交后时分别保留未提交／结果未知。

若 test_device_recovery_windows 未被发现、出现跳过、超时、互斥体状态异常或退出码非零，不算通过。保留完整控制台输出、Python 版本、提交号、命令和退出码到该设备的 .local/ 记录；不要把私人路径、设备信息或截图写进共享文档。

## 逐项核对

- [ ] A 与 B 使用两个不同的临时项目路径；B 的显式测试配置指向 A 项目内同一恢复权威。
- [ ] A 持锁期间，B 取得租约失败，不发送模拟动作。
- [ ] A 正常记录释放并释放租约后，B 可取得租约并读到同一恢复权威。
- [ ] A 持锁并写入模拟动作后以非正常退出结束；最后句柄关闭后，B 可取得新命名互斥体，但仍从 A 的项目目录找到原状态。
- [ ] 只写入意图时中断：恢复结果为 not_submitted，不调用发送器；继续任务必须换新动作ID与计划ID。
- [ ] 已写入“可能提交”标记后中断：恢复结果为 submitted_unknown；重复恢复只读，不重放原动作。
- [ ] 新观察必须匹配原设备身份和动作ID，且时间晚于提交边界；缺失、陈旧、错身份、损坏或不可读都停在“需核实”。
- [ ] 观察核实结果后，动作ID、结果和证据引用仍可读取；下一动作须重新读取身份、画面并规划。

每项自动化结果应与命令输出一致。这里验证的是 Windows 进程、命名互斥体和文件行为；即使全部通过，也不表示设备入口已接入。本地代码仍需 W03-07—09 将租约、动作意图和结果观察放到真实派发边界，再通过相应检查后才可开放下游任务。

本清单不验证突然断电、磁盘损坏、把旧备份整体覆盖回权威目录、网络共享语义或真实模拟器动作。不得为验收故意断电或恢复覆盖文件。
