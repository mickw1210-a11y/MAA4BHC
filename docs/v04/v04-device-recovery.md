# W03-04 设备异常退出与恢复

状态：Mac 离线原型通过，待目标 Windows 双进程、双副本复验。设备派发仍受阻；该原型没有接入设备入口。

先读[租约与持有者诊断](v04-device-lease.md)、[设备调用链](v04-device-call-chain.md)、[动作结果契约](v04-action-results.md)，再看 app/device_lease.py、app/action_result.py、app/device_recovery.py 与相应测试。

## 要解决的问题

项目副本 A 取得设备租约后异常退出。最后一个句柄关闭后，副本 B 可以新建同名互斥体。现有日志按项目根定位，另一副本缺少发现 A 记录和核查未决动作的协议。B 必须先判断旧持有者和上次动作，才能决定是否允许重新规划。重新取得租约只解决当前争用。

## 候选比较与原型选择

| 候选 | 优点 | 风险与退出条件 |
| --- | --- | --- |
| 单一权威目录，位于明确指定的项目副本内；其他副本通过本机可信配置指向它 | 只有一份动作序列，不需要合并；A、B读取同一身份、持有者、动作意图与结果 | 权威副本必须仍在原位置且可读；配置缺失、路径失效、身份不符或记录损坏时停止。不会遍历未知目录，也不使用项目外位置 |
| 每个副本各存一份，再由配置列出其他副本记录 | 本副本可以独立写入 | 新副本、移动、删除或缺少任一配置都会使发现不完整；多个记录需要处理并发分叉、重复恢复和合并冲突，不能自动证明哪份最新 |

原型采用第一种。配置必须显式指定权威所属项目根、其内部的恢复目录和随机 authority_id。B 的本机配置指向 A 的权威目录；这些本机配置不提交到 Git。配置的 authority_id 与状态文件同时存在时才算已初始化。路径或状态文件缺失后，打开操作失败关闭，不会自动初始化；初始化只能走单独的显式 provision 分支。此设计将数据留在指定项目目录内，未使用注册表、用户配置目录或其他项目外存储。

## 原型记录协议

app/device_recovery.py 是 W03-04 离线协议原型，不取得 Windows 租约，也不派发设备动作；实际接入留到 W03-07—09。

1. 在设备租约取得后，记录当前持有者的 PID、线程ID、进程创建FILETIME、取得时间和身份摘要。
2. 副本 B 只有在匹配 PID 与创建标记的前一进程已退出，或 PID 已被复用时，才接续未正常释放的记录。存活或状态未知均停止。
3. 动作先写入并刷新最小意图，包含设备身份摘要、动作ID、计划ID、前置观察ID和动作载荷摘要。隐私连接值、项目路径、账号与实际动作参数不写入。
4. 再持久写入“可能已提交”边界；只有两次保存均成功返回，调用方才可进入派发。任一保存失败都禁止发送。
5. 崩溃时若只有意图且没有提交边界，按协议记录为 not_submitted，不能重放原动作，必须另建计划与动作ID。若提交边界已存在但没有结果，写成 submitted_unknown 并停在只读核实。
6. 只有设备身份、动作ID、结果都匹配，且观察时间晚于提交边界的新观察，才可记录 verified_success 或 verified_failure，并保存观察ID与证据引用。重复检查和重启不派发原动作。
7. 尚有未决动作时不能记录正常租约释放。结果核实后，下一动作仍须重新读取身份、画面和计划。

状态文件使用同目录临时文件、文件刷新及原子替换；事件带顺序号和哈希链。显式 authority_id 用来区分已配置权威和首次初始化。哈希链能检测内容损坏和局部顺序变化，但不能检测把完整权威文件整体恢复到较旧的有效副本；本原型不提供防回滚的外部单调计数器。不要以旧备份覆盖运行中的恢复权威。

## Mac 离线验证

2026-11-17，使用两个项目内隔离目录和合成设备身份运行：

    .local/test-venv/bin/python -W error::DeprecationWarning -m unittest -v tests.test_device_recovery

11 项通过，覆盖跨副本定位、首次初始化与记录丢失区分、持有者退出／PID复用／状态未知、意图和提交边界写入失败不发送、异常退出后的 not_submitted 与 submitted_unknown、新鲜匹配观察核实、重复检查不重放、错误权威／身份／损坏记录失败关闭，以及项目外路径拒绝。测试没有连接设备、MuMu、ADB 或游戏。

同时运行 tests.test_device_recovery_windows 与 tests.test_device_lease，共 8 项 Windows 专属用例在 Mac 按平台条件跳过。Mac 不能验证 Windows 命名互斥体或目标文件系统行为；目标命令及逐项检查见[Windows 双副本复验清单](w03-04-windows-revalidation.md)。原始控制台日志在本机 .local/logs/w03-04-recovery-offline-20261117.log。

当前边界：原型只证明 Python 模拟状态机和本机文件写入协议，不代表它已接入 device_lease.py、Bridge、MaaDevice、开发CLI或真实观察器；单文件恢复也不证明断电、磁盘损坏或回滚安全。目标 Windows 复验前，不解除 W03-04 关口，不接入 W03-07。
